Dashboard

How this dashboard works

Nine sections, in the order they appear on the page. Everything a visitor can read is in one of them.

Emptying a field never blanks the page. If you clear a heading and save, the page keeps the words it already had. You cannot accidentally wipe the site by deleting text.

Except the optional things. The two hero buttons, the two “see all” links, References, and the first address line are meant to be removable — empty their label and they disappear from the page. Every field like that says so underneath.

Opening the editor

The editor lives at a localhost address served by this computer, so it starts with one command here and then opens in a browser on this machine — not on a phone or another device. Once it is open you sign in with Login with GitHub, and everything you save is committed straight to the repository; the live site catches up about a minute later. Online mode is a one-time setup that puts the same login on the live /admin/ page, after which this computer is not needed at all — the steps are on the dashboard page.

There is a second route if you want to work without internet. Run npx decap-server alongside the file server and the editor offers Work with Local Repo instead of the GitHub login. Saves then land in the files in your folder and nothing reaches GitHub until you push them yourself, which is what Saving and publishing below describes.

Getting Terminal into the folder

Commands have to run inside the portfolio folder — Documents/GitHub/Tusher-Portfolio — and Terminal opens in your home folder instead. The line in the next step carries the folder with it, so you can skip this; it is here for the other commands on this page, like git push. Either way works:

  • Type the folder in. Open Terminal — press ⌘ Space, type Terminal, press Return — then paste this line and press Return: cd ~/Documents/GitHub/Tusher-Portfolio
  • Or start from Finder. Control-click the Tusher-Portfolio folder and choose Services → New Terminal at Folder; the window opens already inside it. If that menu item is missing, switch it on under System Settings → Keyboard → Keyboard Shortcuts → Services → Files and Folders.

To check you are in the right place, run ls. It should list index.html, admin and content. If you see your own documents instead, the cd line did not take.

Start the server

Open Terminal — press ⌘ Space, type Terminal, press Return — then paste the line below and press Return. It walks into the folder and starts the server in one go, so it does not matter where Terminal opened:

  • cd ~/Documents/GitHub/Tusher-Portfolio && python3 -m http.server 8124

Leave that window open. Closing it, or pressing Control C in it, stops the editor.

Open the editor

  1. Open http://localhost:8124/admin/#/collections/website in a browser on this computer.
  2. Press Login with GitHub and allow the permission it asks for. The nine sections of the site appear as a list.
  3. Open a section, change what you want, and save. The change is committed to GitHub for you, and the live site shows it about a minute later.

The port number is not fixed — any address that begins with localhost opens the editor, as long as the number matches the server you started.

Saving here publishes. There is nothing else to run: the change goes to GitHub as you save it, and GitHub Pages rebuilds the page within a minute or so.

On the offline route it does not. If you started npx decap-server and chose Work with Local Repo, saves land in the files in your folder and stay there until you push them — see below.

Saving and publishing

Signed in with GitHub, saving is the whole of it: press the Published button at the top right of the editor and choose the publish option in its menu. The change is committed for you, and the line beside the button tells you whether anything is still unsaved. Wait about a minute and refresh the site — GitHub rebuilds the page after every commit, which is what takes the minute.

On the Work with Local Repo route the same button only writes the change into the file in your folder; the live site does not move until you send it yourself. In Terminal, in the portfolio folder, run:

  • git add -A && git commit -m "Update portfolio" && git push

Then wait the same minute and refresh.

What each section changes

2 · About & what I cover Your portrait beside the hero, the three cards under it, and the About paragraphs.
3 · Selected work The list of stories. A story with no link shows a Pending tag instead.

Adding a photograph

Open 4 · Photography, press Add Photographs, upload the picture, and write a caption. It appears in the homepage row and on the gallery page at the same time.

The Category field is what the filter buttons on the gallery page sort by, so it has to match one of the buttons letter for letter — Environment and environment are two different things. A button with no photographs behind it stays hidden, and the preview on the right will tell you when that happens.

Adding a film

Open 5 · Video and paste the whole YouTube address from your browser — youtube.com/watch?v=…, youtu.be/… and Shorts links all work. The still picture is pulled from YouTube automatically; if the preview shows no picture, the link could not be read.

Links inside text

In the About paragraphs, the “what I cover” cards, the job bullet points and the lines under a credential, you can write a link as [the words](https://example.com). Everywhere else, plain text is safest.

If something looks wrong

  • An edit has not appeared. Give it a minute, then refresh. The page reads fresh content every time, so a hard refresh is rarely needed.
  • A photograph is missing. Check the preview on the right — an entry with no picture uploaded is skipped.
  • A whole block vanished. One of the optional labels was emptied. Write the label back in and it returns.
  • The page will not open at all. The python3 -m http.server 8124 window has stopped. Start it again and reload the address.
  • It offers “Work with Local Repo” instead of the GitHub login. An npx decap-server is running somewhere. Stop it with Control C and refresh, or carry on with that route and push the changes yourself.
