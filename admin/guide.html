Dashboard

How this dashboard works

Nine sections, in the order they appear on the page. Everything a visitor can read is in one of them.

Emptying a field never blanks the page. If you clear a heading and save, the page keeps the words it already had. You cannot accidentally wipe the site by deleting text.

Except the optional things. The two hero buttons, the two “see all” links, References, and the first address line are meant to be removable — empty their label and they disappear from the page. Every field like that says so underneath.

Signing in

Two steps, and they do different jobs.

Step 1 — Admin and password. A lock on the door of this page. It keeps other people out of the editor, and the dashboard is not even downloaded until it is passed. It lasts until you close the browser.

Step 2 — GitHub. Saving a change means writing to your repository, so nothing is ever published without GitHub's permission. There are two ways to give it, and the sign-in card offers whichever is available.

With a token

This is the way that works today, from any computer or phone, with nothing to install anywhere. A token is a long password you make on GitHub and paste in once.

  1. On GitHub open Settings → Developer settings → Personal access tokens → Fine-grained tokens and press Generate new token.
  2. Under Repository access choose Only select repositories and pick Tusher-Portfolio.
  3. Under Repository permissions set Contents to Read and write. Nothing else is needed.
  4. Choose how long it should last, generate it, and copy it — GitHub shows it once and never again.
  5. Paste it into the dashboard and press Open the editor.

A token that cannot do the job is refused on the spot, with the reason: it has expired, or it cannot see this repository, or it can read but not write. Nothing is saved until one passes.

Tick “stay signed in” only on your own computer. Ticked, the token is remembered until you sign out. Left unticked it is forgotten the moment the browser closes — which is what you want on a borrowed laptop.

A token never goes into a file. It belongs in the browser and nowhere else. If one ever escapes, delete it on GitHub — the same page you made it on — and make another.

Sign out, bottom right of the dashboard, forgets the token and the password together.

Tokens can be given an expiry date. If GitHub stops accepting a saved one, the dashboard says so and asks for a new one; no work is lost.

Switching the GitHub button on

Log in with GitHub is the tidier way in — no token to keep, nothing stored in the browser — but it needs one small service of its own. GitHub will not hand out a login to a site that cannot keep a secret, and a site made only of files cannot keep one. That service is free and the code for it is already written: open admin/login-helper.js and follow the five steps at the top of the file. The last step puts its address on the base_url line in admin/config.yml, and the button switches itself on as soon as that line is there.

Until then the button stays hidden rather than opening a page that cannot work. If it is ever set up and later misbehaves, the address /admin/?token=new asks for the token door instead.

Saving and publishing

  1. Open a section, change what you want.
  2. Press Save. Nothing is live yet.
  3. Press Publish → Publish now.
  4. Wait about a minute, then refresh the site. GitHub rebuilds the page after every publish, which is what takes the minute.

Adding a photograph

Open 4 · Photography, press Add Photographs, upload the picture, and write a caption. It appears in the homepage row and on the gallery page at the same time.

The Category field is what the filter buttons on the gallery page sort by, so it has to match one of the buttons letter for letter — Environment and environment are two different things. A button with no photographs behind it stays hidden, and the preview on the right will tell you when that happens.

Adding a film

Open 5 · Video and paste the whole YouTube address from your browser — youtube.com/watch?v=…, youtu.be/… and Shorts links all work. The still picture is pulled from YouTube automatically; if the preview shows no picture, the link could not be read.

Links inside text

In the About paragraphs, the “what I cover” cards, the job bullet points and the lines under a credential, you can write a link as [the words](https://example.com). Everywhere else, plain text is safest.

If something looks wrong

  • An edit has not appeared. Give it a minute, then refresh. The page reads fresh content every time, so a hard refresh is rarely needed.
  • A photograph is missing. Check the preview on the right — an entry with no picture uploaded is skipped.
  • A whole block vanished. One of the optional labels was emptied. Write the label back in and it returns.
  • You were sent back to the sign-in card. GitHub stopped accepting the saved token — it expired, or it was withdrawn. Make a new one and paste it in. The card says when that is what happened.
