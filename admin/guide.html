Dashboard

How this dashboard works

Nine sections, in the order they appear on the page. Everything a visitor can read is in one of them.

Emptying a field never blanks the page. If you clear a heading and save, the page keeps the words it already had. You cannot accidentally wipe the site by deleting text.

Except the optional things. The two hero buttons, the two “see all” links, References, and the first address line are meant to be removable — empty their label and they disappear from the page. Every field like that says so underneath.

Opening the editor

The dashboard runs in either of two modes. Local mode works on this computer today: no sign-in, no GitHub token, no online service — the editor writes straight into the files in your folder. Online mode is a one-time setup that puts a real Login with GitHub button on the live /admin/ page, so the site can be edited from any browser. The steps for turning it on are on the dashboard page; everything below describes local mode.

Open Terminal in the portfolio folder

Every command below has to run inside the portfolio folder — Documents/GitHub/Tusher-Portfolio. Terminal opens in your home folder instead, so you have to walk it over first. Either way works:

  • Type the folder in. Open Terminal — press ⌘ Space, type Terminal, press Return — then paste this line and press Return: cd ~/Documents/GitHub/Tusher-Portfolio
  • Or start from Finder. Control-click the Tusher-Portfolio folder and choose Services → New Terminal at Folder; the window opens already inside it. If that menu item is missing, switch it on under System Settings → Keyboard → Keyboard Shortcuts → Services → Files and Folders.

To check you are in the right place, run ls. It should list index.html, admin and content. If you see your own documents instead, the cd line did not take.

Start the two windows

  1. In that window, run npx decap-server and leave it running. The first run downloads the tool, so it needs internet.
  2. Open a second Terminal window with ⌘ N, get into the same folder again, then run python3 -m http.server 8000. Leave this one running too.
  3. Open http://localhost:8000/admin/ and choose Work with Local Repo. The port number is not fixed — any address that begins with localhost opens the editor, as long as the number matches the server you started.

Both windows have to stay open while you edit. Closing one, or pressing Control C in it, stops the editor.

Your edits save into the project folder immediately. They do not become public until you commit and push them yourself.

To publish: use git add -A && git commit -m "Update portfolio" && git push. GitHub Pages usually updates within a minute.

Saving and publishing

  1. Open a section, change what you want.
  2. Press the Published button at the top right of the editor and choose the publish option in its menu. Despite the name, in local mode this only writes the change into the file in your folder — the live site does not change yet. The line beside the button tells you whether anything is still unsaved.
  3. Back in Terminal, run the three Git commands above. In online mode this step does not exist: saving commits to GitHub itself.
  4. Wait about a minute, then refresh the site. GitHub rebuilds the page after every push, which is what takes the minute.

What each section changes

8 · Credentials Education, fellowships & training, and extracurricular activities — three columns.

Adding a photograph

Open 4 · Photography, press Add Photographs, upload the picture, and write a caption. It appears in the homepage row and on the gallery page at the same time.

The Category field is what the filter buttons on the gallery page sort by, so it has to match one of the buttons letter for letter — Environment and environment are two different things. A button with no photographs behind it stays hidden, and the preview on the right will tell you when that happens.

Adding a film

Open 5 · Video and paste the whole YouTube address from your browser — youtube.com/watch?v=…, youtu.be/… and Shorts links all work. The still picture is pulled from YouTube automatically; if the preview shows no picture, the link could not be read.

Links inside text

In the About paragraphs, the “what I cover” cards, the job bullet points and the lines under a credential, you can write a link as [the words](https://example.com). Everywhere else, plain text is safest.

If something looks wrong

  • An edit has not appeared. Give it a minute, then refresh. The page reads fresh content every time, so a hard refresh is rarely needed.
  • A photograph is missing. Check the preview on the right — an entry with no picture uploaded is skipped.
  • A whole block vanished. One of the optional labels was emptied. Write the label back in and it returns.
  • The editor will not open, or the pictures cannot be uploaded. The npx decap-server window has stopped. Start it again and refresh the editor.
